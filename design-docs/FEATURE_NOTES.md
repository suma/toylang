## trait 拡張 / `dyn Trait`

  - **trait ジェネリクス対応** (ITER-PROTOCOL-TRAIT、2026-05-07): `trait Foo<T, U>` 宣言と `impl Foo<i64, str> for Counter` 形 impl をサポート。trait 側の generic params は impl 側の `trait_type_args` で置換されてから conformance 比較される (`Option<T>` + T→i64 は `Option<i64>` として impl と一致)。stdlib `core/std/iter.t` も `pub trait Iterator<T> { fn next(&mut self) -> Option<T> }` の実宣言になり、user は `impl Iterator<i64> for Counter` を書ける
  - **デフォルトメソッド本体** (A1、2026-05-18): trait シグネチャに `{ ... }` 本体を付けると、その method を omit した impl は default body を inherent method として継承する。`expand_trait_defaults_in_pool` AST mutation pre-pass が trait 宣言を走査して default body を持つ method を index 化、各 `impl <Trait> for <T>` の `methods` Vec に synthesize した `MethodFunction` を append。**全 backend (interpreter / AOT / cranelift JIT) で動作** — 既存の inherent-method dispatch をそのまま通るため backend 側の変更は不要 (3-way `assert_consistent` で pin)。`Self` / `self` は impl context で resolve、default 同士の相互呼び出し OK、impl 側で同名 method を書けば override される。**制約**: 現状は generic trait の default body 内で trait の型パラメータ `T` を参照するパターンは未対応 (T → 具体型の substitution は A2 以降)
  - **多重 trait bound `<T: A + B>`** (A2、2026-05-18): generic parameter に複数の trait を `+` で連ねて要求できる。`fn describe<T: Greet + Named>(x: T) -> str { x.greet().concat(x.name()) }` で T は両 trait を実装する型のみ受け入れ、body 内では両方の method を call 可能。実装は **`TypeDecl::TraitIntersection(Vec<DefaultSymbol>)`** 新 variant + 既存 `generic_bounds: HashMap<Sym, TypeDecl>` 形式の維持 (`Identifier(t)` は単一 bound、`TraitIntersection(...)` は複数) で、HashMap 値型を変えず最小侵襲。Parser は `:` 後の最初の type を読んだ後 `+` を peek、見つかれば追加 trait 名を Identifier として連結。Type checker は call-site bound check で AND (全 trait 実装必須)、method dispatch で OR (最初に method を持つ trait を採用)。`module_integration::remap_type_decl` も `TraitIntersection` arm 追加。**全 backend で動作** — backend は monomorphized concrete type だけを見るため bound list 自体を観測しない (3-way `assert_consistent` で pin)。エラーは多重 bound の場合「struct `X` does not implement trait `Y`」で先頭の不適合 trait を pinpoint
  - **`dyn Trait` Phase 1 / interpreter** (A5-P1、2026-05-18): `&dyn TraitName` 形式の trait object dispatch を interpreter で実装。`fn describe(a: &dyn Animal) -> i64 { a.sound() }` の引数に任意の `impl Animal for X` を満たす struct を渡せる。実装は **`TypeDecl::Dyn(DefaultSymbol)`** 新 variant (trait symbol を持つ)、新 lexer keyword `dyn`、`parse_type_declaration` で `dyn TraitName` を消費。type checker は `is_arg_compatible_dyn_aware` ヘルパで context-aware coercion (`&Struct → &dyn Trait` および bare `T → &dyn Trait` auto-borrow、`struct_implements_trait` 経由で trait conformance を check)、receiver が `Dyn(trait_sym)` の method dispatch を trait signature table 経由で resolve。interpreter runtime arg check (`evaluation/call.rs:656`) は expected が `Dyn` のとき skip (static check が canonical、runtime は erasure ベース)
  - **`dyn Trait` Phase 2-MVP-F / AOT (`&mut self` + compound return combined)** (A5-P2-MVP-F、2026-05-19): MVP-C の `&mut dyn` writeback と MVP-D/E の compound return を**同時に**扱う最後のエッジケース (`fn step(&mut self) -> Pair`)。**新 IR**: `InstKind::CallWithSelfWritebackCompound { target, args, ret_dests: Vec<LocalId>, self_dests: Vec<LocalId> }` — cranelift call の results が `[ret_leaves..., self_writeback_leaves...]` で返るのを `ret_dests.len()` で split して 2 つの dest vec に `def_var`。**Thunk**: `lower_dyn_thunk_body` を 4-way switch に refactor — `self_is_mut && !ret_is_compound` (MVP-C scalar)、`self_is_mut && ret_is_compound` (MVP-F new)、`ret_is_compound` (MVP-D/E)、scalar/Unit。新 arm は `flatten_compound_leaf_types(ret_ty)` で ret_dests を確保、impl の writeback leaves で self_dests を確保、`CallWithSelfWritebackCompound` を emit、`emit_writeback_ptrwrites` helper (MVP-C/F 共有、PtrWrite × N で `data_ptr` に書き戻し) を呼び、最後に `LoadLocal × ret_dests + Return(values)` で multi-value 返却。**Caller side 変更なし** — `CallIndirectFnStruct/Tuple/Enum` (MVP-D/E) と `pending_dyn_mut_writebacks` (MVP-C) が独立に機能、組み合わせ時も自動的に正しく振る舞う。**Backend coverage**: interpreter / AOT (MVP-A〜F の全組合せ) / JIT silent fallback。consistency test `dyn_trait_mut_self_struct_return_round_trip` 追加 (`Cell { n: i64 } -> Pair { x, y }` を 2 回 step、計 69)、MVP-A〜E の 10 件と合わせて 11 件 3-way 一致。**A5-P2 (AOT) は実用面で完了**。**今後の phase**: JIT (A5-P3)、`Box<dyn Trait>` (A5-P4)
  - **`dyn Trait` Phase 2-MVP-E / AOT (tuple + enum return)** (A5-P2-MVP-E、2026-05-19): MVP-D の struct return パターンを **tuple return** (`fn get_pair(self) -> (i64, u64)`) と **enum return** (`fn maybe(self) -> Option<i64>`) まで拡張。**新 IR**: `InstKind::CallIndirectFnTuple { callee, args, param_tys, ret_tuple_id, dests }` と `CallIndirectFnEnum { ..., ret_enum_id, ... }` (MVP-D の `CallIndirectFnStruct` のミラー)。Codegen は `flatten_struct_to_cranelift_tys` が `Type::Tuple` / `Type::Enum` も再帰展開できる事実を再利用 (sig.returns に flat leaves を push、`def_var` で multi-result を dests に分配)。**Thunk**: `lower_dyn_thunk_body` に `Type::Tuple` / `Type::Enum` arm 追加、新 helper `lower_dyn_thunk_compound_return` + 列挙型 `CompoundReturnCallKind { Struct, Tuple, Enum }` で 3 形態の共通化 (`CallStruct` / `CallTuple` / `CallEnum` を kind で選択して emit、leaf list は `flatten_compound_leaf_types` から)。**Caller**: `lower_dyn_method_call` に `Type::Tuple` → `CallIndirectFnTuple + pending_tuple_value`、`Type::Enum` → `CallIndirectFnEnum + pending_enum_value` 分岐追加。**Let-binding 統合**: MVP-D の 3 分岐 helper を統合 `lower_let_dyn_method_compound_return` に書き換え — 1 回の `lower_method_call` 呼び出しの後、`pending_struct_value` / `pending_tuple_value` / `pending_enum_value` のうち新規に set された channel を検出して該当 `Binding` を install (`had_*` snapshot で再 emit 回避)。**Backend coverage**: interpreter (P1) / AOT (MVP-A empty + MVP-B scalar + MVP-C nested + `&mut dyn` + MVP-D struct return + MVP-E tuple / enum return) / JIT silent fallback。consistency tests `dyn_trait_tuple_return_round_trip` と `dyn_trait_enum_return_round_trip` を追加、MVP-A〜D の 8 件と合わせて 10 件全部 3-way 一致。**今後の phase**: `&mut self` + compound return 同時 (`CallWithSelfWritebackStruct` 等の追加 IR が必要、稀)、P3 (JIT)、P4 (`Box<dyn Trait>`)
  - **`dyn Trait` Phase 2-MVP-D / AOT (compound struct return)** (A5-P2-MVP-D、2026-05-19): trait method が **struct を return する** ケース (`fn build(self: Self) -> Pair`) を AOT で landing。実装は **`InstKind::CallIndirectFnStruct { callee, args, param_tys, ret_struct_id, dests }`** 新 IR (mirror of `CallStruct` for indirect calls)。codegen は `flatten_struct_to_cranelift_tys` で struct return を flat leaves に展開、`sig.returns` に push、call_indirect の multi-result を `dests[i]` 各 LocalId に `def_var` で分配 (parallel to existing `CallStruct` arm)。**Thunk 側**: `lower_dyn_thunk_body` で `ret_ty` が `Type::Struct(id)` のとき plain `Call(impl)` の代わりに `CallStruct { target, args, dests }` で impl を呼び、各 leaf を `LoadLocal` してから `Terminator::Return(values)` の multi-value return body にすべて渡す。**Caller 側**: `lower_dyn_method_call` で `ir_ret_ty == Type::Struct(_)` のとき `allocate_struct_fields` で field bindings を確保、`flatten_struct_locals` で flat な `dests` を作り `CallIndirectFnStruct` を emit、`pending_struct_value` を set して `Ok(None)` を返す。**Let-binding 統合**: `let_lowering.rs` に新 helper `lower_let_dyn_method_struct_return` を追加 — receiver が `Binding::DynTraitObj` で trait method が struct を return する `val p = m.build()` パターンを intercept、`pending_struct_value` を consume して `Binding::Struct { struct_id: <recovered>, fields }` を `name` に install。**重要 fix**: `lower_dyn_method_call` の `lower_param_or_return_type` 呼び出しで `&Default::default()` を渡していたので compound 型を resolve できなかった → `self.struct_defs` / `self.enum_defs` を渡すように修正、これで `Identifier(Pair)` → `Struct(StructId)` の resolve が走る。`flatten_compound_leaf_types` を `pub(super)` に visibility 拡張、`flatten_struct_to_cranelift_tys` も同様。**Backend coverage**: interpreter (P1) / AOT (MVP-A empty + MVP-B scalar + MVP-C nested + `&mut dyn` + MVP-D struct return) / JIT silent fallback。consistency test `dyn_trait_struct_return_round_trip` 追加、MVP-A/B/C の 7 件と合わせて 8 件全部 3-way 一致。**今後の phase**: tuple return / enum return (MVP-E)、P3 (JIT)、P4 (`Box<dyn Trait>`)
  - **`dyn Trait` Phase 2-MVP-C / AOT (nested struct + `&mut dyn Trait` writeback)** (A5-P2-MVP-C、2026-05-19): MVP-B の uniform thunk ABI を拡張して **nested compound field** (`Outer { inner: Inner { v: i64 }, tag: u64 }`) と **`&mut dyn Trait` writeback** (`fn pump(c: &mut dyn Counter) -> i64 { c.bump() }` で trait method の mutation が caller の struct binding に伝播) に対応。Nested field は MVP-B の `flatten_struct_locals` / `flatten_compound_leaf_types` が既に再帰対応していたので追加 codegen 変更なし、test pin のみ。**`&mut dyn` writeback** は両端で実装: (1) **thunk 側** — trait method の `self_is_mut` が true のとき、impl method (`self_writeback_types` で trailing returns を持つ) を `Call` ではなく **`InstKind::CallWithSelfWriteback`** で呼ぶ。返ってきた post-mutation leaves を per-leaf `PtrWrite { ptr=data_ptr, offset, value, value_ty }` で stack slot に書き戻す。(2) **caller 側** — outer call が returns したら caller-frame stack slot から `PtrRead` で各 leaf を読み戻し、`StoreLocal` で元の struct binding の leaf local に書き戻す。これは `FunctionLower::pending_dyn_mut_writebacks: Vec<DynMutWriteback>` state field と `drain_dyn_mut_writebacks()` helper で実装、`lower_call_args_with_target` で `&mut dyn` arg ごとに entry を push、`call.rs::lower_call` が Call/CallWithSelfWriteback emit 直後に drain。**新 IR**: `Function::param_dyn_trait` を `Vec<Option<DefaultSymbol>>` から `Vec<Option<(DefaultSymbol, bool)>>` に widening (second tuple element = is_mut)。新 struct: `lower/mod.rs::DynMutWriteback { slot_addr, struct_leaves, dest_locals }`、`PendingThunkBody::self_is_mut: bool` を追加。**重要 fix**: `lower/program.rs` の `self_writeback_types` setup loop で **`&mut dyn Trait` params をスキップ** — writeback は stack slot 経由なので return-value tuple appending しない (これがないと "1 writeback dests but callee declared 2 writeback returns" の compile error が出る)。**Backend coverage**: interpreter (P1) / AOT (MVP-A empty + MVP-B scalar + MVP-C nested + `&mut dyn`) / JIT は silent fallback。consistency tests: `dyn_trait_nested_struct_round_trip` / `dyn_trait_mut_self_round_trip` 追加、MVP-A/B の 5 件と合わせて 7 件すべて 3-way 一致。**今後の phase**: trait method の compound return (`-> Pair`)、P3 (JIT)、P4 (`Box<dyn Trait>`)
  - **`dyn Trait` Phase 2-MVP-B / AOT (scalar field 対応)** (A5-P2-MVP-B、2026-05-19): MVP-A の empty struct 限定を、**scalar field を持つ struct** (`Cell { v: i64 }` / `Pt { x: u64, y: u64 }` 等) まで拡張。**統一 dispatch ABI**: trait method 呼び出しを常に `(data_ptr: U64, ...user_args) -> R` シグネチャに揃え、各 `impl Trait for Type` ごとに **thunk 関数** (`toy_dyn_thunk_<trait>_<struct>_<method>`) を pre-declare + drain loop で body 生成。Thunk body は `data_ptr` から各 leaf を `PtrRead` で読んで impl method に `(leaves..., user_args)` で forward。**Coercion site**: struct に leaf がある場合、`Function::dyn_coerce_slots` に entry を追加 (byte size = `compute_byte_size`)、`InstKind::DynCoerceSlotAddr` で stack slot の addr を取得、各 leaf を natural-sum byte offset に `PtrWrite` で書き込み、その addr を data_ptr として渡す。Empty struct は MVP-A の sentinel `data_ptr = 0` を維持 (cranelift が size-0 stack slot を許さないため、かつ thunk が data_ptr を deref しないので安全)。**Vtable population**: thunk FuncId を `module.vtables` に格納 (impl FuncId 直接ではなく)、`define_vtables` (codegen) は無変更で済む。**新 IR**: `Function::dyn_coerce_slots: Vec<u32>` / `InstKind::DynCoerceSlotAddr { slot_idx }`。新 struct: `PendingThunkBody` / 新 helper: `dyn_struct_leaf_layout` (program.rs)、`FunctionLower::lower_dyn_thunk_body`。**Backend coverage**: interpreter (P1) / AOT (MVP-A empty + MVP-B scalar field) / JIT は silent fallback。consistency tests: `dyn_trait_scalar_field_round_trip` / `dyn_trait_two_scalar_fields_round_trip` / `dyn_trait_heterogeneous_field_round_trip` を追加、MVP-A の 2 件 + MVP-B の 3 件で計 5 件すべて 3-way 一致。**今後の phase**: MVP-C (compound / nested field、`&mut self` writeback)、P3 (JIT)、P4 (`Box<dyn Trait>`)
  - **`dyn Trait` Phase 2-MVP-A / AOT (empty struct only)** (A5-P2-MVP-A、2026-05-19): empty struct (`Dog {}` / `Cat {}` 等、フィールド 0 個) を対象に **fat pointer ABI + vtable + 動的ディスパッチ** を AOT compiler で実装。`&dyn Trait` は IR で `Type::Tuple([U64, U64])` (data_ptr, vtable_ptr) として表現、cranelift の tuple ABI で 2 cranelift スカラに flatten される。各 `impl Trait for Type` ごとに `toy_vtable_<trait>_<struct>` global data を declare、関数アドレス relocation で trait 宣言順に方法ポインタを埋め込む。**重要 fix**: `define_zeroinit` ではなく `define(zeros)` を使うこと — Apple `ld` (arm64-darwin25) は `__DATA,__bss` 内の関数アドレス reloc で segfault する known bug があるため。vtable emit は **lazy** — `InstKind::VtableAddr` instruction が実際に参照する `(trait, struct)` pair だけ emit (stdlib 全 impl の vtable を emit すると 33 個の unused reloc で同じ ld bug を踏む)。call site の coercion (`describe(d)` where d: Dog) は `lower_call_args_with_target` で param が `&dyn Trait` のとき `(const U64 0, VtableAddr { trait, struct })` の 2 leaf を push。dispatch site は `Binding::DynTraitObj { trait_sym, data_ptr_local, vtable_ptr_local }` を引数 binding として作成し、`lower_dyn_method_call` で trait 宣言から method index を resolve、`PtrRead vtable_ptr + idx*8` で fn_ptr を load、**新 IR instruction `InstKind::CallIndirectFn`** (closure ABI の implicit env を持たない indirect call) で呼び出す。新 IR: `Module::trait_method_order` / `Module::vtables` / `Function::param_dyn_trait` / `InstKind::VtableAddr` / `InstKind::CallIndirectFn`。新 binding: `Binding::DynTraitObj`。新 codegen helper: `CodegenSession::define_vtables` / `declare_vtable_imports`。**Backend coverage**: interpreter (P1)、cranelift JIT は eligibility で silent fallback、AOT は empty struct のみ動作 (3-way `assert_consistent` の `dyn_trait_empty_struct_round_trip` / `dyn_trait_heterogeneous_dispatch_round_trip` で pin)。**今後の phase**: P2-MVP-B (scalar field + thunk)、P2-MVP-C (compound field)、P3 (JIT)、P4 (`Box<dyn Trait>`)

## クロージャ

- **クロージャ / ラムダ**: `fn(params) -> R { body }` 形式の anonymous function literal、関数型は `fn (T1, T2) -> R` (推奨、`fn` prefix で意図を明示) または `(T1, T2) -> R` (bare 形、後方互換) を parameter / return / val 注釈 / **struct field 型** 位置に書ける。bind は `val f = fn(x: i64) -> i64 { x + 1i64 }` (closure literal から型推論)、または `val f: fn (i64) -> i64 = fn(x: i64) -> i64 { x + 1i64 }` (明示注釈)。struct field に格納する場合は `struct S { f: fn (i64) -> i64 }`、call は `s.f(args)` (field-call dispatch)。free var capture は creation time の snapshot (primitive は値コピー、compound は Rc 共有)。**backend coverage**: interpreter は full support (literals + captures + HOF args + return + nest)、JIT は silent fallback、**AOT compiler は env-based ABI 統一 (Phase 6b) で direct call + HOF 引数の両方で capturing/non-capturing 両対応** — 残: closure を return / field 格納、narrow int capture (Phase 6c)。captures は 8-byte scalar (i64/u64/f64/bool) のみ。closure value = env_ptr (`[fn_ptr, cap0, cap1, ...]` を heap allocate)、callee body の第 1 param は env: U64。詳細は [`docs/language.md` → Closures](docs/language.md)。
