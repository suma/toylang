# ELEMENT-BORROW — 容器の要素を、複製せずに名指す

> 状態: **設計中。実装は無い。** todo.md の CONTAINER-ELEM-DROP
> (未実装、★★★) が指す文書。2026-09-19 に書き起こした。
>
> 決まっているのは**方向**だけである: `get` は値を返すまま据え置き、
> **`borrow` を新設して `&T` を返す**。その形を入れるために言語側で
> 何が要るか、どこから削るかを以下に置く。

## 0. 何が壊れているか

```rust
var conns: Vec<TcpStream> = Vec::new()
conns.push(cl)
val s: TcpStream = conns.get(0u64)   # 要素の**浅い複製** (fd 番号は同じ)
# `s` の束縛が死ぬと drop glue が fd を閉じる。
# 表にはまだ載っているのに、次の write は EBADF
```

`get` が返すのは要素の**浅い複製**である (`String` なら data / len / cap
の 3 語)。資源は要素と共有しているのに、**呼び出し側の束縛は所有者として
扱われる** — compound を返す method 呼び出しから束縛したローカルには
drop glue が付くため。結果として 1 つの資源に所有者が 2 人いる。

heap ブロックでは見えない (アドレスを再利用しないヒープで `free` は
冪等)。OS が 1 度しか返さないもの — fd — で初めて牙を剥く。

**stdlib は `__builtin_ptr_read::<T>` で回避している** (`Vec::sort` が
use-after-free になったときにそうした)。利用者側には `unsafe` な builtin
に降りる以外の道が無い。

**兄弟だった MATCH-PAYLOAD-COPY は 2026-09-19 に直した** — `match` の腕は
payload の複製ではなく別名を張るようになった。あちらは lowering が持って
いる情報だけで決まったが、こちらは**「この method の戻り値は別名か、
新しい所有者か」を型で言う**必要がある。それが `borrow` である。

## 1. 採る形

```rust
impl<T> Vec<T> {
    fn get(&self, i: u64) -> T       # 今までどおり。値が欲しい人に
    fn borrow(&self, i: u64) -> &T  # 新設。要素を名指す
}
```

- **`get` は変えない。** スカラーの要素 (`Vec<u64>`) は値で受け取るのが
  自然で、呼び出し側 270 か所 (stdlib 35 / POC 239) を触らずに済む
- **`borrow` は所有しない。** 参照は drop glue を持たないので、
  「2 人目の所有者」が生まれない
- **名前は `borrow`。** `get_ref` / `at` / `ref` も候補だった。
  `borrow` を採るのは、**この呼び出しが何をするか**を言っているからで
  ある — `get` が値を渡すのに対し、こちらは貸すだけで、返ってきた名前は
  容器より長生きできない (2-e)。`get_ref` は「参照で返す `get`」としか
  言っておらず、生存期間の話が名前に出てこない

## 2. 言語側に足りないもの

今の言語で `borrow` は**書けない**。参照は「引数の位置にだけ現れ、
lowering で消えるもの」であり、REF-Stage-2 (e) が 2 か所で止める。

| 止まる場所 | 診断 | 例 |
|---|---|---|
| 戻り型が参照 | `[E0010] function \`pick\` declares a reference type in its return position; references cannot escape their referent's frame` | `fn borrow(&self, i: u64) -> &T` |
| 束縛が参照 | `binding \`e\` annotates a reference type; references cannot be stored in val / var bindings` | `val e: &T = v.borrow(0u64)` |

**両方を緩めないと使えない。** 戻せても束縛できなければ、
`v.borrow(i).len()` のような形しか書けず、compiled レーンは
「呼び出し結果へのメソッド呼び出し」を受け付けない (RUNTIME_GAPS G16)。

### 2-a. 何を許すか — 「引数の再借用」だけ

戻せる参照を**引数から派生したものに限る**。Rust の省略ライフタイムと
同じ規則で、`&self` を取る method が `&self` の中を指す参照を返すのは
許し、ローカルを指す参照を返すのは今までどおり拒否する。

```rust
fn borrow(&self, i: u64) -> &T     # OK: self から派生
fn bad(&self) -> &T { val t = ...   t }   # NG: 自分のフレームを指す
```

`Vec<T>` の要素は `self.data` (生ポインタ) の先にあって、`self` の
フィールドを辿った先ではない。したがって **`unsafe` な builtin が 1 つ要る**:

```rust
__builtin_ptr_ref::<T>(p: ptr, offset: u64) -> &T
```

「この番地を `T` として名指す」だけのもので、`__builtin_ptr_read` の
参照版である。`unsafe fn` の中でしか呼べない (POINTER P6 の対象を 1 つ
増やす) ので、生の番地から参照を作れるのは stdlib の実装だけになる。

**参照は enum の payload にも入れる。** `Dict` は「無い」を答えねば
ならないので、Rust と同じ `Option<&V>` の形を採る:

```rust
impl<K, V> Dict<K, V> {
    fn get(&self, k: K) -> Option<V>       # 今までどおり
    fn borrow(&self, k: K) -> Option<&V>  # 新設
}
```

これは 2-a の「引数の再借用」を**型の中に持ち込む**ことになるが、
前例がある — `[E0026]` は `fn f() -> Option<Span<u8>>` を捕まえるために
入った検査で、**すでに enum の中の窓を見ている**。参照も同じ経路に載る。

`Option<&V>` を受ける側は `match` で開く。腕の束縛は 2026-09-19 から
**別名**なので (MATCH-PAYLOAD-COPY)、開いた `&V` は複製されず、
所有者も増えない — この 2 つが噛み合って初めて `Option<&V>` が
安全に書ける。

### 2-b. どこまで生かすか — escape は `[E0026]` を再利用

`Span<T>` の脱出検査 (WINDOW-ESCAPE、`[E0026]`) が既に
「**終わりが見えるものから派生した値は、それより長生きする場所へ
到達してはならない**」を見ている。参照の束縛にも同じ規則を掛ける:

```rust
fn f() -> ??? {
    var v: Vec<String> = Vec::new()
    v.push(String::from_str("x"))
    val e = v.borrow(0u64)   # `e` は `v` から派生
    e                          # [E0026]: `v` はこの波括弧で死ぬ
}
```

検査の実体を共有できるかは実装時に見る (`region_check` 系の 1 つに
「参照も窓と同じ」を足すのが最小)。

### 2-c. 読みだけにする (`&mut` は後回し)

**`borrow` は `&T` を返す。`get_mut` (`&mut T`) は入れない。**
`&mut` の compound 引数は今も「複製して呼び、書き戻す」形で実装されて
おり (todo の REF-Stage-2 residual)、**戻り値には書き戻す先が無い**。
真の pointer-passing が入るまで、要素の書き換えは `set` / `__setitem__`
に任せる。

### 2-d. `&T` は読みだけ透過

束縛できるようになった `&T` で何が書けるか。**読む側は `T` と同じに書け、
所有型を値として取り出すことだけができない。**

| 書けること | 例 |
|---|---|
| フィールドを読む | `e.x` |
| メソッドを呼ぶ (`&self` / 値レシーバ) | `e.len()` |
| 算術・比較・出力 (スカラー) | `e + 1u64` / `e == 3u64` / `println(e)` |
| `&T` を要求する引数へ渡す | `take(e)` |
| **スカラーを値として取り出す** | `val n: u64 = e` |

| 書けないこと | 例 | 理由 |
|---|---|---|
| **所有型を値として取り出す** | `val v: String = e` | それは浅い複製で、**所有者が 2 人になる** — この文書が塞ごうとしている当のもの。欲しいなら `val v = e.clone()` と書く |

スカラーの透過性は**今あるもの**である (`fn f(p: &u64) -> u64 { p + 1u64 }`
は既に通る)。束縛にも同じ規則を掛けると、**パラメータの `&T` と束縛の
`&T` で書けることが揃う** — 場所によって書けることが変わる形を作らない。

線の引き方は新しくない。`[E0014]` (move) が既に「所有型かどうか」で
振る舞いを変えており、覚えることは増えない。検査も
「`val v: T = <&T の式>` を、`T` が所有型のときだけ拒否する」1 つで済む。

**却下した案**: `&T` を完全に透過にする (所有型の取り出しも許す) と罠が
そのまま復活する。`*e` のような明示的な deref を入れると、`T` → `&T` は
暗黙で逆は明示という非対称を抱える。束縛では算術も禁じる案は、
パラメータとの食い違いが残る。

### 2-e. 容器の大きさが変わったら、参照は保証しない

**`borrow` の戻りが生きている間に容器の大きさが変わったら、その参照が
名指していた要素は保証されない。** `push` / `pop` / `clear` / `reserve` —
再確保しうる操作すべてが対象で、**検査はしない**。書いた人の責任である。

理由は 2 つ。借用が生きている間の変更を止めるのは借用検査そのもので、
この言語は持っていない (CONCURRENCY.md §2-a と同じ話)。そして
`Span<T>` が既に同じ約束の下にある — 窓は元のバッファが動けば意味を失い、
それは `[E0026]` (生存期間) では捕まらない。**規則を 2 つに分けない。**

危ないのは「動かなくなる」ことではなく、**動いてしまう**ことである。
ヒープはアドレスを再利用しないので、再確保のあとの古い参照は
**解放済みの領域を読んで正しかった頃の値を返す**。`Span` の escape を
検査に入れたのも、まさにこれを実測したからだった (POINTER.md §未解決の
論点)。だから文書にはこう書く — 「容器を変えたら、その前に取った参照は
捨てる」。

```rust
val e = v.borrow(0u64)
v.push(x)          # ここで `e` は無効になりうる (検査されない)
e.len()            # 何が返るかは保証しない
```

## 3. これで CONTAINER-ELEM-DROP は消えるか

**消えない。減る。** `get` は今までどおり所有者を増やすので、
`val s: TcpStream = conns.get(0u64)` は相変わらず fd を閉じる。
変わるのは「**正しい書き方が存在する**」ことである:

```rust
val s = conns.borrow(0u64)   # 名指すだけ。閉じない
```

罠そのものを消したいなら、所有型を要素に持つ容器の `get` を
**型検査で拒否する** (「`T` が所有型なら `borrow` を使え」) 段が要る。
これは移行を伴うので、`borrow` が入って実際に使われてから決める。

## 4. 段取り

| | 中身 | 単独で出荷できるか |
|---|---|---|
| **E1** | `__builtin_ptr_ref::<T>` と、参照を返せる規則 (引数の再借用のみ、enum payload の中も含む) | 型検査だけなら可。使い道はまだ無い |
| **E2** | 参照をローカルに束縛できるようにする + `[E0026]` 相当の escape 検査 + 2-d の「所有型は取り出せない」検査 | **E1 と合わせて 1 つ**。ここで初めて書ける |
| **E3** | `Vec` / `SoaVec` / `Span` / `Column` に `borrow`、`Dict` に `Option<&V>` を返す `borrow` | stdlib だけ。呼び出し側は無変更 |
| **E4** | `poc/logsearch` の接続表を `Vec<TcpStream>` + `borrow` に戻す | 実証。今は番号の表で回避している |
| **E5** | 所有型要素の `get` を拒否する (任意) | 移行を伴うので、E4 の感触を見てから |

**4 レーンのどれでも同じ答えになること**が条件である。参照は lowering で
消えるので、compiled レーンでは「要素の leaf を読む」に落ちる — つまり
**今の `get` と同じコード**になり、違いは drop glue が付かないことだけ。
tree-walker は元から別名なので、そちらは意味が変わらない。

## 5. 未決の論点

無し。§1〜§4 で決めた形のまま E1 に着手してよい。残る判断は実装中に
出てくるもの (escape 検査を `region_check` のどこに載せるか、`Dict` の
`Option<&V>` が lowering でどう畳まれるか) で、設計の分岐ではない。

## 6. 却下した案

- **`get` の戻りを一律 `&T` にする** — 呼び出し側 270 か所に触れる。
  スカラーが透過なので多くは無変更で済む見込みだが、**確認できない量**で
  あり、`get` が値を返すことに依存した形 (`val v = a.get(i)` を書き換えて
  から `set` で戻す) が壊れる
- **窓だけで解く** (`v.at(i) -> Ptr<T>`) — 言語を変えずに済むが、
  `get` の罠はそのまま残り、利用者は `unsafe` に降りる
- **所有の判定を出自で決める** (「新しく作られた値だけが所有する」) —
  結局「この戻り値は別名」を型で言う必要があり、`&T` を別の綴りで
  再発明することになる
